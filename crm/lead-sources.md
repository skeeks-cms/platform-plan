# CRM: «Откуда узнали» — рекламный источник сделки

Направление CRM: у сделки (`CmsLead`) есть ответ «откуда клиент о нас узнал»,
он заполняется сам, где это возможно, и выбирается в один клик, где нет.
Есть канал «Пришёл в салон» для покупателей, пришедших лично. Отчёт
показывает, какая реклама приносит сделки и деньги.

## Повод

Магазин отделочных материалов с салоном работает на платформе и хочет
перестать вести сделки в таблице Excel. В таблице у менеджеров два столбца:
«Источник» и «Рекламный источник»; в CRM ответа на эти вопросы нет. Через
формы сайта приходит около 10 % обращений, остальное — звонки и люди,
пришедшие в салон. Маркетолог клиента предупредил: если заставить менеджеров
заполнять много полей, учёт не приживётся.

Что было в CRM до этого направления: у сделки технический `source_type` —
*как* сделка попала в систему (форма, звонок, письмо, бот, вручную) — и
utm-метки. Нет ответа *откуда узнали* и нет канала «пришёл лично».

## Решение владельца (05.11.2026)

Не делать произвольные поля под одного клиента, а сделать общую доработку
платформы:

1. **Справочник «Откуда узнали»** у каждого сайта: название, порядок,
   активность, необязательный код и правила сопоставления. Список ведёт сам
   клиент в настройках CRM. Начальные пункты: «Яндекс Директ», «Поиск (SEO)»,
   «Яндекс Карты», «2ГИС», «Авито», «Соцсети», «Вывеска / проходил мимо»,
   «Рекомендация», «Повторный клиент», «Рассылка», «Другое».
2. **Поле сделки «Откуда узнали»** — пункт справочника, может быть пустым.
   Видно в карточке, форме, списке (колонка и фильтр) и в API.
3. **Автозаполнение**, только если поле пустое; выбранное человеком не
   перезаписывается:
   - заявка с сайта — по utm-меткам (правила пункта), без меток — по
     переходу (поисковик → «Поиск (SEO)»);
   - заявка после письма или рассылки → «Рассылка»;
   - звонок — по номеру, на который позвонили (коллтрекинг), если телефония
     этот номер знает; иначе — точка расширения на следующий шаг.
   Сопоставление — точка расширения ядра, ядро не зависит от пакетов
   коммуникаций.
4. **Канал «Пришёл в салон»** — новый `source_type` «Визит в салон / офис».
   Выбирается при ручном создании сделки; форма сайта с настройкой «канал:
   визит» создаёт сделку с этим каналом — для регистрации посетителей по
   QR-коду в салоне.
5. **Ручной ввод в один клик**: при ручном создании сделки поле стоит на
   видном месте. Настройка «обязательно для ручных сделок» по умолчанию
   выключена.
6. **Отчёт**: сделки, успешные сделки и сумма по пунктам «Откуда узнали» за
   период с разбивкой по каналу — в существующем разделе отчётов CRM, без
   нового раздела.

«Источник» из таблицы клиента = канал (`source_type`), «Рекламный источник»
= «Откуда узнали». Два понятия, одно поле для ручного выбора.

## Этапы

| Этап | Что | Состояние |
|---|---|---|
| О-1 | Справочник, поле сделки, автозаполнение по меткам, переходу и письмам, канал «визит», форма с каналом, настройки, отчёт, API | в работе |
| О-2 | Коллтрекинг: номер, на который позвонили, → пункт справочника | после О-1, по готовности телефонии с номером назначения |
| О-3 | Проверка у клиента с салоном: перенос столбцов таблицы в справочник | после выпуска О-1, сайт клиент обновляет сам |

## Открытые вопросы

- Подключение коллтрекинга у конкретного оператора телефонии — отдельное
  решение владельца, в О-1 не входит.
