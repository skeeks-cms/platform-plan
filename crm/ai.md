# CRM: ИИ

План работы ИИ в CRM: этап 8 (пакет `cms-ai`) и ранний практический шаг —
разбор базы и личные предложения через MCP. Проверенные договоры кода —
в умении: [ai-read-api.md](https://github.com/skeeks-cms/skeeks-cms-package-development/blob/main/references/ai-read-api.md) (чтение) и
[ai-actions.md](https://github.com/skeeks-cms/skeeks-cms-package-development/blob/main/references/ai-actions.md) (действия и отправка через API).

## Замысел

ИИ — пользователь CRM со своей ролью, инструменты — те же `cms-mcp`. Уровни
самостоятельности для бота, переписки и вида действия: выключен,
подсказывает (черновик на подтверждение), действует и сообщает, полностью сам
(цены, сроки, деньги — никогда сам). Если менеджер взял диалог или ответил —
ИИ молчит. Сценарий группового чата: клиент пишет «поправить баннер» → разбор
переписки (с паузой, чтобы собрать сообщения) → проверка открытых задач
компании → задача → ответ в чат → по выполнении правило пишет в чат. Журнал
решений `cms_ai_run` с отметками «верно/неверно». Сообщения клиента — данные,
а не команды: права инструментов ограничены привязанной компанией и этой
перепиской; лимиты. Модель выбирается на уровне сайта (152-ФЗ: российская или
зарубежная). Пакет `cms-ai`.

## Разбор базы и личные предложения

Согласовано с владельцем 24.10.2026. Задача: пройти базу компаний, клиентов
и лидов вместе с историей общения, понять, кому что предложить (бывшие
клиенты, устаревшие сайты, сферы с готовыми решениями — например
`/solutions/plitka`, остывшие лиды), и писать людям индивидуально, прикладывая
предложение. Все бизнес-процессы — личная ссылка, «открыто» в ленте, задача
«Позвонить», отписка, отчёт — работают так же, как у менеджера.

**Где живут инструменты.** `cms-mcp` только подключает провайдеры
инструментов (`McpComponent::$providers`, `McpToolProviderInterface`);
инструменты почты, рассылок и согласий — в `cms-communication`, предложений —
в `cms-proposal`, каждый пакет регистрирует свой провайдер, если `cms-mcp`
установлен. Права — через OAuth-пользователя и `forManager()`, как в
интерфейсе.

**ИИ-1. Чтение** (`cms.communication.read` и аналоги):
- история клиента одним списком для лида, компании, клиента: звонки, письма,
  комментарии, задачи, сделки, счета, отправки предложений и их открытия
  (существующий `cms_company_timeline_get` писем и предложений не показывает);
- письма и переписки клиента с текстом без цитат и подписей, без вложений;
- предложения: список и карточка, готовые общие Презентации, КП;
- «можно ли писать»: `MailingPolicy` (отписки, стоп-лист, согласие по теме).

Как сделано (24.10.2026):
- Как устроены история клиента (`cms_crm_history_get`), обзор клиента
  (`cms_crm_client_overview_*`), точка расширения `cms-mcp`, права и
  маскировка персональных данных — умение,
  [ai-read-api.md](https://github.com/skeeks-cms/skeeks-cms-package-development/blob/main/references/ai-read-api.md).

**ИИ-2. Действия** — только с `confirm=true`, тем же путём, что у менеджера:
- черновик письма в ящике ответственного с приложенным предложением (личная
  ссылка создаётся при отправке); менеджер правит и отправляет сам — режим
  по умолчанию;
- кампания 4B с личным текстом каждого получателя: ИИ заполняет получателей
  и тексты, менеджер просматривает и запускает; дальше — ограничение
  скорости, отписка, отчёт, задача при открытии;
- отметка «подготовлено ИИ» у письма, отправки и записи в ленте (кто
  подготовил — ИИ через какой клиент, кто отправил — человек).

Как сделано (24.10.2026, подробно — README `cms-communication`, раздел «Действия ИИ-клиентов»):
- Три инструмента `cms-communication` (`cms_comm_draft_create`,
  `cms_comm_campaign_create`, `cms_comm_campaign_recipient_add`; запуска
  кампании и отправки нет намеренно), черновик тем же путём, что в «Почте»,
  проверки по строкам, лимиты, журнал и отметка «Подготовлено ИИ» — умение,
  [ai-actions.md](https://github.com/skeeks-cms/skeeks-cms-package-development/blob/main/references/ai-actions.md).
- Проверено на стенде настоящим HTTP-вызовом REST под OAuth-входом
  (OAuth-клиент рабочего компьютера, администратор): черновик №43 лиду 69
  с Презентацией №10 → отправлен из «Черновиков» с ящика
  тестовый ящик сотрудника (письмо 1928, отправка 37, «Подготовлено ИИ» в ленте и
  в карточке предложения) → открытие ссылки → задача «Позвонить» №5871;
  отказы «черновик уже ждёт», «отписан от темы» (лид 50), «писали 24.10»
  (лид 51), 21 строка → «Не больше 20»; кампания №5 с личными письмами
  лидам 70–72 осталась черновиком (поле `status` в аргументах не действует,
  `cms_comm_campaign_launch` — 404), запуск сотрудником отправил письма
  1929–1931 с отметкой. Светлая, тёмная тема и 375 px.

**ИИ-2б. Полный цикл личного письма через API** (задание владельца
24.10.2026: сегмент — магазины плитки с сайтом без оплат и активного
сотрудничества, 2–3 клиента для пилота, затем малыми партиями; Презентация
№1 «Сайт для магазина плитки и керамогранита — SkeekS» на проде уже
создана в интерфейсе). Как сделано:
- Проверка черновика и `check_token`, отправка только владельцем черновика,
  идемпотентность через `cms_comm_api_send`, честные состояния, раздельные
  права (`cms.communication.write` / `mail_send`, `cms.proposal.write`),
  темы и Презентации через API, отметка «отправлено ИИ через API» — умение,
  [ai-actions.md](https://github.com/skeeks-cms/skeeks-cms-package-development/blob/main/references/ai-actions.md), «Sending through the API».
- Сайт лида в обзоре: `company_sites` — сайты его компании; `has_site` для
  лидов учитывает сайт компании.
- Проверено на стенде: тест `tests/ai-send.php` (51 проверка); живая отправка
  лиду 120 (тестовый адрес студии) с тестового ящика сотрудника через
  `McpComponent::executeTool()` (транспорт REST): черновик 69 → проверка →
  отправка → повтор тем же ключом вернул письмо 2054 → `sent`, доставка
  `not_confirmed` → открытие по личной ссылке → `opened`, просмотров 1, задача
  «Позвонить» №5872; статус прочитан и настоящим HTTP-вызовом REST под
  OAuth-входом. Инструменты с новыми правами по HTTP проверяются после
  повторного входа (старый токен их не видит — так и задумано).

**ИИ-2в. Файлы, тестовые отправки, назначение письма** (задание владельца

- На skeeks.com в тестовом списке — тестовая карточка компании →

- Проверено на стенде: `tests/ai-letters.php` (51 проверка, MIME собран

**ИИ-2д. Лимиты ИИ меняет в CRM тот, кто управляет почтой** (задание владельца
24.10.2026; выпущено в `cms-communication` 1.11.0). Раньше лимиты задавала только конфигурация
сайта (`communication.aiLimits`), которую выкладка на боевой не трогает.
- **Где:** «Настройки» → «Настройки почты» → «Работа ИИ через API»
  (`components\AiApiSettings`; право `cmsCommunication/admin-cms-comm-settings`
  «Почта: управлять почтовыми ящиками и «Настройками почты»» — им же теперь
  открываются «Почтовые ящики» и доступы к ящикам, по умолчанию у
  администраторов, раньше там была роль администратора): писем в день через
  API, черновиков и получателей кампаний в день и за запрос, дни «не писать
  повторно», дни рабочей переписки и сотрудничества, выключатель «Разрешить
  отправку писем через API».
- **Порядок:** значение из CRM → `communication.aiLimits` → значения по
  умолчанию (`AiActions::limitSources()`; страница показывает действующее
  значение и источник). Пустое поле — запасной уровень; 0 — значение
  (ничего не разрешено, у `recentDays` — без проверки повтора).
- **Хранение:** общий механизм настроек компонента сайта (как «Переходы из
  писем»), без своей таблицы; чтение `AiApiSettings::forSite()` с кешем на
  запрос.
- **Отправка выключена:** проверка и отправка отказывают
  (`api_send_disabled`) с подсказкой, где включить; черновики готовятся.
- Проверено на стенде: `tests/ai-offer.php` (54 проверки: порядок,
  сохранение, отказ при выключенной отправке и при нуле), страница в
  светлой, тёмной и мобильной темах; значения стенда возвращены.

**ИИ-2е. Черновики доступных сотрудников** (решение владельца 03.11.2026;
выпущено в `cms-communication` 1.21.0 и выложено на skeeks.com 03.11.2026). Повод:
черновики рассылки «Сайт по 152-ФЗ» лежат в «Почте» сотрудника, а владелец
хочет отправлять их через API под своей учётной записью — API отказывал
`not_own`; отдельный вход сотрудника в API не делаем.
- **Решение:** «доступный сотрудник» — подчинённые по отделам, администратору
  — все сотрудники; согласие сотрудника не нужно — руководитель или
  администратор сам смотрит, правит, отправляет и передаёт его черновики; и в
  API, и в «Почте».
- **Как отправляется:** письмо уходит из ящика владельца черновика, с его
  подписью, в счёт его дневного лимита; все проверки прежние (политика
  рассылок, 30 дней, адрес из карточки, лимиты). В письме, ленте клиента и
  журнале отправок через API видно, кто фактически отправил («по
  поручению»). Чужой черновик — по-прежнему отказ `not_own`.
- **«Почта»:** в «Черновиках» переключатель «Мои / сотрудник», галочки
  («Удалить», «Передать» нескольких), «Передать черновик» в окне письма;
  передача есть и в API. Передать можно только себе или работающему
  доступному сотруднику; черновики уволенного сотрудника остаются доступны.
- Независимая проверка 03.11.2026 нашла 16 замечаний (в том числе чтение
  писем сотрудника через его черновик и двойную отправку одного черновика);
  все исправлены до выпуска, подробности — пакет, «История работ пакета».
- Договор кода — умение,
  [ai-actions.md](https://github.com/skeeks-cms/skeeks-cms-package-development/blob/main/references/ai-actions.md),
  «Drafts of managed employees»; устройство и проверка — пакет, «История
  работ пакета».

**ИИ-3. Разбор базы** — рабочая сессия на боевом сайте, не код: сначала
только чтение и отчёт (почему кандидат подходит, какое предложение, черновик
текста; сайты кандидатов ИИ открывает и оценивает: дизайн, мобильная
версия, HTTPS, год в подвале); владелец отмечает, кому писать; затем
черновики или кампания.

**Персональные данные.** Разбор передаёт данные клиентов внешней модели
(152-ФЗ, трансграничная передача). Вариант по умолчанию — передавать
деловую часть (компания, сфера, история без телефонов и адресов); решение
за владельцем перед ИИ-3.
