# Домены: продажа через API регистратора

Состояние: **план записан 20.11.2026, реализация не начата.**

Студия не регистратор. Домены клиентов регистрируются и продлеваются на
аккаунте студии у аккредитованного регистратора reg.ru через его API
(REG.API 2), а клиенту домен продаётся как обычная услуга CRM: счёт, оплата,
срок, продление. Студия оплачивает домен регистратору со своего баланса.

## Решения владельца

**20.11.2026**

1. **Регистратор — reg.ru, через REG.API 2.** Работаем на текущем аккаунте
   студии с Рег.решением «Многодоменов .ru/.рф»: цена продления .ru/.рф
   снижается ступенями с ростом числа доменов на аккаунте. Партнёрская
   программа reg.ru и переоформление договора на юрлицо — позже, при росте
   (см. «Ограничения»).
2. **Продление — только после оплаты клиентом.** Счёт клиенту выставляется
   заранее, домен продлевается у регистратора после оплаты. Автопродление на
   стороне reg.ru выключено: студия не оплачивает домены за клиента.
3. **Цена для клиента — своя, по зонам.** Прайс по доменным зонам в
   настройках: цена регистрации и цена продления отдельно. Не привязана к
   цене регистратора, его ступеням и акциям; себестоимость учитывается
   отдельно для контроля маржи.
4. **Первый этап — работа менеджера в CRM.** Импорт существующих доменов,
   карточка домена, счета на продление, регистрация и перенос менеджером.
   Заказ домена клиентом в кабинете — отдельным этапом вместе с п. 14
   «Самостоятельные клиенты сайта, заказ услуг в кабинете»
   ([crm/links-contract.md](../crm/links-contract.md)).
5. **Каждый домен — отдельная услуга CRM.** У домена свой срок, свой счёт на
   продление и своя история оплат; домен не входит ресурсом в общую услугу
   клиента (например, «Сайт и хостинг»). При импорте (Д1) для каждого
   домена создаётся или подбирается своя услуга «Домен».

## Исходные факты (проверено 20.11.2026)

**REG.API 2** (документация: https://www.reg.ru/reseller/api2doc)

- Запросы `https://api.reg.ru/api/regru2/<категория>/<функция>`, ответы JSON;
  сложные параметры — `input_format=json`, `input_data`.
- Вход по логину и **альтернативному паролю API** (не основной пароль
  аккаунта) или по подписи RSA. Запросы принимаются только с IP-адресов из
  белого списка в «Настройках API»; новый адрес начинает работать через
  несколько минут.
- Лимит — 1200 запросов в час на аккаунт и на IP. Регистратор просит:
  хранить сведения о доменах у себя, к API обращаться только за изменениями,
  изменения выполнять асинхронно, WHOIS запрашивать напрямую у WHOIS-серверов.
- Тестовый доступ (логин и пароль `test`) проверяет параметры, но ничего не
  выполняет и не списывает деньги.
- Нужные функции: `domain/create` (регистрация), `domain/transfer` (перенос
  от другого регистратора по коду authinfo), `service/renew` (продление),
  `service/set_autorenew_flag`, `domain/update_nss` и `domain/get_nss`
  (DNS-серверы), `domain/update_contacts`, `service/get_list` (все домены
  аккаунта со сроком и состоянием одним запросом), `service/get_info`,
  `user/get_balance`, `user/get_persons` (администраторы и признак
  идентификации), `domain/get_prices`.
- Регистрация .ru/.рф/.su требует полных данных администратора: для
  организации — названия, ИНН, КПП, адресов, телефона, email; для физлица —
  ФИО, паспортных данных, даты рождения, адреса. Ошибки возвращаются по
  каждому полю (`INVALID_CONTACTS`). Профили контактов через API не
  создаются, данные передаются в каждом запросе.
- Оплата — с баланса аккаунта (`pay_type=prepay`); без денег операция не
  выполняется.
- `domain/get_prices` с авторизацией отдаёт цены тарифа аккаунта, но для
  Рег.решения — цену лучшей ступени, а не текущую. Фактическая себестоимость
  — сумма `payment` в ответе операции.

**Ограничения**

- Без партнёрского статуса недоступны `domain/check` (свободен ли домен) и
  `domain/get_suggest` (подбор имени). Свободен ли домен — проверяем по WHOIS.
- С 01.09.2026 партнёром регистратора для .ru/.рф/.su может быть только
  юрлицо — резидент РФ. Договор студии с reg.ru сейчас оформлен не на юрлицо;
  для перехода в партнёры его надо переоформить.
- **Идентификация администраторов через Госуслуги (ЕСИА), 569-ФЗ.** С
  01.09.2026 без неё администратор домена .ru/.рф/.su не может
  зарегистрировать или продлить домен, сменить DNS-серверы, администратора
  или регистратора. Идентификацию проводит только регистратор: он сам
  присылает администратору письмо со ссылкой. Студия не может пройти её за
  клиента — только предупредить, проследить и помочь. Часть администраторов
  на аккаунте студии её ещё не прошла.

## Модель

**Ресурс «Домен»** в `cms-hosting` — по образцу DNS-зоны и SSL-сертификата:

- имя (punycode) и зона;
- владелец и услуга: компания, человек, своя услуга CRM (`cms_deal_id`, одна
  услуга — один домен); активность
  услуги и оплаченный клиентом срок берутся из услуги, не копируются;
- регистратор и идентификатор домена у регистратора (`service_id`);
- **срок регистрации в реестре** — отдельное поле. Это факт реестра, его нельзя
  путать со сроком услуги (сколько клиент оплатил студии);
- состояние у регистратора (не зарегистрирован, активен, приостановлен,
  освобождён), последняя ошибка, время последней сверки;
- администратор домена: ссылка на контрагента CRM (организация) или на
  человека; признак идентификации через Госуслуги;
- DNS: серверы студии (ns1–ns3) или серверы клиента; связь с DNS-зоной.

**Журнал операций** с регистратором: что отправлено, что ответил, номер счёта
регистратора, сумма списания, кто запустил, ошибка. По нему считается
себестоимость и сверяются расходы.

**Клиент API регистратора** и **фоновые задания** (cms-job, своя очередь с
ограничением частоты): регистрация, перенос, продление, смена DNS-серверов,
смена контактов, сверка. Пароль API хранится вне базы, как ключи PowerDNS;
сервер, с которого идут запросы, вносится в белый список IP регистратора.

**Цены:** прайс по зонам (регистрация, продление) в настройках хостинга;
себестоимость — по журналу операций.

## Процессы

1. **Сверка.** Раз в сутки `service/get_list`: обновить сроки и состояния,
   показать домены на аккаунте без записи в CRM и записи без домена у
   регистратора.
2. **Продление.** За N дней до срока в реестре — счёт клиенту и
   напоминания; после оплаты — задание продления, обновление срока в реестре
   и срока услуги. Не оплачен — домен истекает; ответственному сотруднику —
   предупреждение до истечения. .ru/.рф после истечения ещё 30 дней можно
   продлить по обычной цене.
3. **Регистрация.** Менеджер проверяет, свободен ли домен (WHOIS), создаёт
   услугу «Домен» и счёт; после оплаты — задание регистрации с DNS-серверами
   студии; после активации — DNS-зона создаётся автоматически.
4. **Перенос к студии.** Код authinfo от клиента → `domain/transfer`; для
   .ru/.рф контакты берутся из реестра.
5. **Баланс.** Проверка перед операцией и раз в сутки; ниже порога —
   уведомление ответственному.
6. **Идентификация.** После регистрации или переноса .ru/.рф/.su и для
   доменов, у которых она не пройдена, — предупредить клиента о письме
   регистратора, задача менеджеру проследить; признак — в карточке домена.

## Этапы

| Этап | Что входит | Состояние |
|---|---|---|
| Д0. Исследование | Проверка API (тестовый и боевой доступ на чтение), условия регистратора, ЕСИА, решения владельца | сделано 20.11.2026 |
| Д1. Импорт и карточка | Ресурс «Домен», клиент API (только чтение), импорт доменов аккаунта, привязка к компаниям и услугам, ежедневная сверка, список доменов с тонами по сроку, признак ЕСИА | не начато |
| Д2. Продление после оплаты | Прайс по зонам, счета на продление заранее, напоминания, продление после оплаты, журнал операций и себестоимость, контроль баланса | не начато |
| Д3. Регистрация и перенос менеджером | Проверка по WHOIS, заказ из CRM, регистрация и перенос заданиями, автоматическая DNS-зона, смена DNS-серверов и контактов | не начато |
| Д4. Заказ клиентом в кабинете | Проверка и заказ домена, оплата в кабинете клиента — вместе с п. 14 плана CRM | не начато |
| Д5. Партнёрство регистратора | Договор на юрлицо, партнёрский статус, `domain/check` и подбор имён через API, больше зон | отложено (решение 20.11.2026) |

Д2 — первый живой сценарий регулярного продления услуги с выставлением счёта.
Общий механизм продления услуг в CRM — этап П4 «Услуги и обслуживание»
([crm/entities.md](../crm/entities.md)), он не начат. Д2 строить так, чтобы
механизм счёта на продление переиспользовался П4, а не стал отдельной копией.
