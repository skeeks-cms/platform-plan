# Решения владельца

Журнал решений владельца платформы по датам. Здесь — суть решения в одну
строку и ссылка на место, где оно записано полностью: в файле плана, в
документе пакета или в умении `skeeks-cms-package-development`. Полный текст
решения в журнал не копируется.

Обозначения мест:
- `crm/…` — файлы этого репозитория;
- «пакет» — [`cms-communication/ARCHITECTURE.md`](https://github.com/skeeks-cms/cms-communication/blob/master/ARCHITECTURE.md);
- «умение» — [`skeeks-cms-package-development/references/`](https://github.com/skeeks-cms/skeeks-cms-package-development/tree/main/references).

Новое решение добавляется сюда в тот же день, когда записано в плане.
Отменённое решение не удаляется: рядом пишется, чем и когда оно заменено.

## 2026-11-05

- У сделки появляется «Откуда узнали» — справочник сайта, который ведёт сам
  клиент; заполняется сам по меткам, переходу и письмам (ручной выбор не
  перезаписывается), выбирается в один клик при ручном создании; новый канал
  «Визит в салон / офис», в том числе через форму по QR-коду; отчёт по пунктам
  с разбивкой по каналу. Общая доработка платформы, а не поля под клиента.
  [crm/lead-sources.md](../crm/lead-sources.md)

## 2026-11-03

- Руководитель (подчинённые по отделам) и администратор (все сотрудники)
  смотрят, правят, отправляют и передают черновики писем сотрудников без их
  согласия — в «Почте» и через API; письмо уходит из ящика сотрудника, с его
  подписью и в счёт его лимита, в ленте видно, кто отправил «по поручению».
  [crm/ai.md](../crm/ai.md), ИИ-2е

## 2026-11-02

- У задачи третий режим начала — «на день»: фиксирован день, время внутри дня
  ставит планировщик; день раскладывается так: булавка, затем «на день», затем
  «по графику»; перегруженный день — «+N ч», задача на другой день сама не
  уходит; невыполненная — на сегодня первой с «Просрочена на N дн.»; форма —
  одно поле «Когда» с необязательным временем; перенос задачи «по графику» на
  день делает её «на день» (заменяет правило 31.10); закреплённые задачи без
  напоминаний и звонков переводятся «на день» командой после «да» владельца.
  [crm/tasks.md](../crm/tasks.md), «Режим „на день“»

- Заявка с сайта, оставленная во время визита по ссылке из письма CRM,
  сразу привязывается к клиенту письма и уходит его основному
  ответственному (без него — отправителю письма); письмо открытой сделки —
  заявка добавляется в неё; письмо кампании — заявка по рассылке.
  [crm/proposals.md](../crm/proposals.md), п. 5

## 2026-10-31

- У каждой задачи есть начало: «закреплено» (выбрал человек, не двигается)
  или «авто» (ближайшее свободное окно графика исполнителя); один общий
  расчёт начала; старые задачи переносятся без изменения видимой раскладки.
  [crm/tasks.md](../crm/tasks.md), пп. 1–5
- Напоминание — необязательное поле любой задачи, уходит «важным»
  уведомлением исполнителю (и автору по галочке); задачи с напоминанием
  помечены колокольчиком. [crm/tasks.md](../crm/tasks.md), пп. 6–7
- Виды задач одним переключателем: день, «Сроки», календарь с полной
  сеткой, Гант с перетаскиванием; общий элемент выбора даты и времени.
  [crm/tasks.md](../crm/tasks.md), пп. 8–10
- Уточнения по задачам: пересчёт авто-задач только по событиям с пометкой
  «перенесена»; своё напоминание приходит и в тихие часы; опоздавшее
  напоминание уходит с пометкой «опоздало»; порядок шагов А, Б, Г, В, Д;
  «не успевает к сроку» — ждёт ответа, что считать сроком.
  [crm/tasks.md](../crm/tasks.md), «Уточнения владельца»
- Необязательный «Крайний срок» задачи: позже него расчётный конец — пометка
  «не успевает» без уведомлений; начало задачи обязательно на уровне базы.
  [crm/tasks.md](../crm/tasks.md), «Крайний срок и обязательное начало»
- Закреплённое время задачи меняется только явным выбором, который человек
  видит: в списке закреплённая задача внутри дня не двигается, на другой
  день — с тем же временем суток; в календаре и Ганте — шаг 5 минут; после
  переноса — «Было → стало» и «Отменить», напоминание переезжает с задачей.
  [crm/tasks.md](../crm/tasks.md), «Перенос закреплённых задач»
- Булавка задачи — переключатель: закрепить на текущем начале сразу, снять —
  после подтверждения; запись в истории с автором; то же в карточке и API.
  [crm/tasks.md](../crm/tasks.md), «Булавка — переключатель»
- По итогам независимой проверки этапа «Задачи»: в Ганте в масштабе «месяц»
  перенос по целым дням с тем же временем суток (исключение из шага 5 минут);
  задача «в работе» — закреплена на начале работы; закрытые и «в работе» не
  двигаются ни через виды, ни через API; задачи событий с рассчитанным
  началом — «авто». [crm/tasks.md](../crm/tasks.md), «Независимая проверка
  и исправления»
- 01.11.2026: булавка задачи везде одинаковая, как у комментариев (пустая серая —
  по графику, заполненная — закреплена); закреплённая задача в списке не
  перетаскивается вовсе. [crm/tasks.md](../crm/tasks.md), «Булавка — одинаковая
  везде»
